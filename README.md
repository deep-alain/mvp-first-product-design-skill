# MVP First Product Design Skill

一组供 AI 助手使用的产品设计与评测 Skill，帮助你把产品想法收敛成可开发的第一版，再用实际输入输出判断 AI 功能是否达到要求。

## 这是什么

Skill 是 AI 助手执行特定任务时读取的一组指令和参考资料。它规定思考重点、判断步骤和交付要求，让任务有一套可重复使用的方法。

这个仓库包含两个 Skill：

| Skill | 主要用途 |
| --- | --- |
| [MVP First Product Design](SKILL.md) | 判断需求价值、收敛范围、设计完整 UI/UX，并自审交付 |
| [AI Product Evaluation](skills/ai-product-evaluation/SKILL.md) | 制定评测标准、建立案例集、分析 Bad Case、比较修改前后结果 |

前者帮助你决定“做什么、做到哪里”，后者帮助你判断“做得怎样、下一步改哪里”。可以单独使用，也可以按产品研发阶段配合使用。

## 能用在哪

- 有一个产品想法，想判断它解决什么问题，用户为什么愿意使用。
- 功能清单越列越长，需要确定第一版保留、简化和延期的内容。
- 已经有 PRD 或原型，需要检查核心流程是否完整、投入是否值得。
- 已经做过 Demo，需要改善视觉层级、中断与结束体验，并明确哪些能力真实可用。
- 做出了 AI 功能，但不知道怎样定义“回答正确”或“体验合格”。
- 遇到 AI 输出错误，需要结合输入、上下文和实际回复分析原因。
- 修改了 Prompt、代码或模型，希望通过固定案例检查改善与退化。

## 怎么用

### 1. 安装需要的 Skill

按所用 AI 助手支持的技能安装方式，添加对应目录：

- MVP Skill：仓库根目录，入口是 `SKILL.md`。
- 评测 Skill：`skills/ai-product-evaluation/`，入口是其中的 `SKILL.md`。

保留各目录内指令、参考资料和脚本的相对路径。支持技能调用的助手可使用下面的名称；也可以将对应指令和任务资料一起提供给 AI。

### 2. 提供任务和已有资料

审查需求时，提供目标用户、需求或 PRD、已有证据、时间和资源约束：

```text
使用 $mvp-first-product-design 评审这个产品需求。
先说明用户问题和核心价值，再划分保留、简化、延期、删除。
给出第一版最短完整流程，以及如何验证它是否有用。

需求和资料：……
```

评估 AI 功能时，提供使用场景、预期行为、实际输入输出和可用日志：

```text
使用 $ai-product-evaluation 评估这个 AI 功能。
先定义成功标准，再建立正常案例、失败案例和边界案例。
分析已有 Bad Case，区分已知事实和原因假设。
提出最小修改方案与回归检查方法。

任务、输入输出和资料：……
```

### 3. 用结果推动下一步

需求评审会整理核心任务、功能取舍、必要质量和验证方法。涉及界面时，继续明确使用情境、视觉方向、组件与关键状态；涉及实现时，检查实际渲染和核心操作，再按请求交付。模拟数据、真实接通能力、已执行与未执行的验证分别说明，不把页面简单等同于 MVP。

已有 Demo 优先在原项目迭代。明确要求直接修改时，执行授权内的修改和自查；只要求评审时，保留在评审范围。打包和部署按本次请求完成，不随每次小改重复产出。

迭代时先明确页面职责、默认状态与用户动作，再检查相关列表、反馈、接口和交付版本。艺术表达可以鲜明，但不应无故阻挡核心内容；指标先明确数据含义和计算依据，再选择图表。复盘区分缺陷、需求变化与审美探索，避免把单个产品的选择推广成通用禁令。

AI 评测会整理判据、案例集、失败证据、候选原因和前后对照，帮助你决定保留、继续验证、撤回或延期。

## 使用例子

以下是便于理解方法的示例，不代表真实业务实验结果。

### 例子一：把维修预约想法收敛成第一版

你想做一个维修预约产品，设想包括预约、支付、会员、积分、聊天、地图调度和智能诊断。

把需求交给 MVP Skill 后，先判断居民真正需要完成什么：提交有效信息，并得到明确的预约处理结果。再围绕这条流程保留必要信息、希望的时间、工作人员确认和状态反馈；其他功能根据证据和现有能力决定是否延期。

最终得到一份有理由的范围清单，以及需要验证的关键假设，而不是直接把所有想法变成开发任务。

[查看完整需求与取舍示例](examples/repair-appointments.md)

### 例子二：分析票据提取中的金额错误

你做了一个 AI 票据提取功能，输入合计为 `12.50 元`，输出却是 `125 元`。

使用评测 Skill，可以先把“金额与币种准确”写成判据，再补入小数金额、整数金额等案例。检查原始输入、传给模型的内容、原始输出和后处理，判断问题可能出现在哪一层。

修改后重跑同一组案例，比较错误是否修复，以及原本正确的案例是否退化。语义判定需要对照输入证据；辅助脚本负责校验记录和汇总评审。

[查看合成案例与记录](examples/ai-evaluation/receipt-extraction/使用说明.md)
