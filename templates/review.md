# MVP 评审模板

只填已有信息。未知项写“未知”，不必为了填满表格编造证据。小改动可缩减本模板。

## 输入

- 产品 / 功能：
- 目标用户与发生需求的情境：
- 当前做法与已观察的问题：
- 主要结果与可观察信号：
- 已有证据及来源（与猜测分开）：
- 用户主动使用的理由：
- 涉及付费时的新增价值与购买证据：
- 时间、资源、平台要求：
- 明确不做的范围：

## 前提结论

- 最弱假设 / 前置能力：
- 决定：继续分解 / 先验证 / 先补前置能力 / 推迟。
- 最小可信实验与会改变决定的证据：

## 核心契约

- 主任务与承诺结果：
- 最短完整流程：
- 当前页面的职责边界、结果去向，以及状态与操作的区别：
- 必须守住的能力与必要质量：

## 范围与验证

- 关键状态、权限和数据完整性要求：
- 暂不支持的边界与人工处理方式：
- 重开推迟项所需的证据：
- 测量基线、窗口及限制：
- 本次仍然未知的事情：

## UI/UX（涉及界面时）

- 使用情境、设备、注意力与输入方式：
- 入口、当前对象/模式与首屏主任务：
- 视觉方向、已有组件与 Token 来源：
- 主要内容、状态反馈与次要设置的层级：
- 中断、结束、返回的数据与资源后果：
- 同一对象在相关页面、反馈和交付物中的信息一致性：
- 涉及指标时的数据含义、计算依据及可支持的判断：
- 需要覆盖的窄屏、长内容、键盘与焦点状态：

## 产出与自审（涉及实现或交付时）

- 本次交付：视觉方案 / 交互原型 / 已接通核心能力的 MVP。
- 运行版本与实际交付目标是否相同，涉及哪些接口及下游约束：
- 可打开的入口、源码或指定交付格式：
- 样例、模拟、真实能力与未接通依赖：
- 实际执行的检查、环境/视口、观察结果：
- 已修复问题与针对性复验：
- 尚未验证的服务、设备或体验：
- 构建、打包、部署是否在本次授权范围，实际是否完成：

## 调用

把以上已填内容提供给 Agent，并要求：使用 $mvp-first-product-design 评审，区分事实与假设，保住核心结果，不凭空补齐用户证据或指标。
